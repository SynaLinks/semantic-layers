# Synalog, as a layer uses it

Synalog is a logic programming language from the Datalog family: every
predicate compiles to SQL and runs on the layer's database. This page is
synalog's own skill, cut to the language, after what changes inside a layer.
The full reference is at <https://synalinks.github.io/synalog/>.

## In a layer

- **One predicate per file.** `concepts/<Name>.l` or `rules/<Name>.l`, with
  front matter: `name` (the predicate that runs; synalog checks the file
  defines it), `description`, `keywords`. Helpers the predicate needs — a
  recursive relation, a staging step — stay in its file; a helper worth
  reusing gets a file of its own.
- **Tables are files too.** `tables/<Name>.l` maps one physical table to a
  PascalCase predicate; it is generated by `semantic-layers connect` — never
  write a `# Tables` section in a concept or a rule, and never name a
  physical table outside `tables/`.
- **Imports name the folder, the file and the predicate**:
  `import concepts.Customer.Customer;`, `import tables.Orders.Orders;`,
  resolved from the layer's folder. Every import must be used.
- **Run from the layer's folder**: `uvx synalog rules/<Name>.l run <Name>`.
  Its `layer.toml` names the engine and the database, and synalog loads the
  secrets from its `.env` — no `--engine`, no `--load`.
- **`@OrderBy` on every concept and rule**, `@Limit` for a ranking.
